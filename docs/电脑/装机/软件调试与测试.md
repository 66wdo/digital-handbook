# 软件调试与测试

装好机、装完系统，下一步不是急着开游戏，而是用几款小软件把「我感觉没问题」变成「数据证明没问题」。这一页按用途分层介绍常用工具：**先识别硬件对不对，再看传感器，再做稳定性测试，最后才是调校和跑分**。所有软件都只是辅助，一次只改变一个变量，才好定位问题。

!!! tip "一条主线"
    **识别型号 → 看传感器温度 → 单烤 CPU / 测内存 → 单烤显卡 → 双烤 → 回到真实游戏验证。** 别一上来就 CPU、显卡、内存一起拉满，那样一旦出错不知道是谁的问题。

## :material-card-search: 硬件信息识别

这类软件只读信息、不施加负载，用来核对「商家给我的、系统认到的、我以为买的」是不是同一件东西。

### 图吧工具箱：懒得一个个找，就用合集

**图吧工具箱是国内免费的 Windows 工具合集（绿色、按分类打包在一个启动器里）**，把装机检测常用软件集成到一起，省得到处找、也避免下到捆绑安装包：

- **硬件识别**：CPU-Z、GPU-Z、主板 / 内存信息；
- **传感器与烤机**：AIDA64（64 / 32 位）、Core Temp、CPU / GPU 烤机、一键烤显存；
- **内存**：TestMem5 等；**硬盘**：CrystalDiskInfo / CrystalDiskMark；
- 此外还收了蓝屏 dump 分析、DirectX 诊断（dxdiag）等小工具。

它本身是「启动器」，不替代你判断，每个软件具体怎么看仍对照本页对应小节；请从官网或可信渠道下载、认准绿色版。像 AIDA64 传感器、蓝屏分析这些工具，后面还会单独细讲。

### CPU-Z：核对 CPU 与内存

**CPU-Z 是一款免费的 CPU/主板/内存信息软件（Windows）**，重点看：

- **CPU 页**：名字、核心/线程、核心电压、当前频率，确认型号和标称一致；
- **Mainboard 页**：主板型号、芯片组、BIOS 版本（判断要不要刷 BIOS）；
- **Memory 页**：内存当前是否**双通道（Dual Channel）**、实际运行频率；
- **SPD 页**：每条内存插在哪个槽、颗粒厂、XMP/EXPO 预设参数。

!!! note "内存频率的「一半」错觉"
    DDR 是双倍速率，CPU-Z 里看到的 DRAM Frequency 约等于等效频率的一半（例如显示 3000MHz 上下，对应 DDR5-6000）。这是正常的，别误以为内存没跑满。

### GPU-Z：核对显卡与 PCIe 链路

**GPU-Z 是一款免费的显卡信息与状态检测软件（Windows）**，重点：

- **Name / 显存 / 着色器数量**：对照官方规格，二手卡用来识别假卡、刷 BIOS 改名卡；
- **Bus Interface（总线接口）**：显示 PCIe 协商状态，形如 `PCIe x16 4.0 @ x16 4.0`；
- **Sensors 传感器页**：核心/显存频率、温度、功耗、风扇转速。

判断显卡是不是跑在满速槽，要配合 **Render Test（渲染测试，点 Bus Interface 旁的问号按钮，让显卡短暂满载）**：桌面待机时链路会自动降速省电，满载后仍停在 `@ x4 / x8`，才需要去查是不是插错槽、通道共享或没插到底，详见《[硬件 · M.2 与 PCIe 通道布局](硬件.md#m2-与-pcie-通道布局)》。

## :material-chart-line: 传感器与实时监控

### HWiNFO：最全的硬件传感器

**HWiNFO（免费，选 Sensors-only）**能读到几乎所有传感器：每个核心的温度/频率/电压、CPU 封装功耗、显卡热点（Hot Spot）与显存温度、主板各路电压、风扇转速、硬盘 SMART。排查「为什么卡、为什么热、为什么掉频」时，它比「娱乐跑分」类软件可信得多。新手只需要关注：CPU 封装温度与功耗、GPU 核心/热点温度、+12V 电压、各盘温度。

### 微星小飞机的 OSD：游戏里实时看数据

**MSI Afterburner（微星小飞机，免费，A/N 卡通用）**自带 RivaTuner Statistics Server，可以在游戏画面角落叠加显示**帧率、CPU/显卡占用与频率温度、显存和内存占用、帧时间**。判断「游戏掉帧到底怪 CPU 还是显卡」时，看 OSD 里谁先占满即可：显卡 99% 是显卡瓶颈，显卡没满而 CPU 某核顶满，是 CPU 瓶颈。

### 怎么判断显卡「有没有发力」

显卡占用没到 100% 不等于没发挥，要结合帧时间和其他硬件一起看（用上面微星小飞机的 OSD）：

- **显卡占用长期 95%～100%、核心频率跑在标称加速频率附近**：显卡已成为瓶颈、在全力输出，想再提帧只能换更强的卡或降画质 / 分辨率；
- **占用没跑满 ≠ 没发力**：网游或老游戏、CPU 带不动、开了垂直同步 / 帧率上限、开了 DLSS/FSR 后负载变轻，都会让占用停在更低水平，都属正常；
- **高 U 低卡（CPU 瓶颈）**：显卡占用忽高忽低上不去，而 CPU 某个核心（游戏常只吃少数几个核）接近 100%、帧时间随场景波动——瓶颈在 CPU，这时换显卡提升有限；
- **高卡低 U（显卡瓶颈）**：显卡持续近满载、CPU 仍有余量，这才是该升级显卡的情形；
- 下结论前先排除：是否锁帧 / 开垂直同步、内存是否单通道、温度或功耗是否撞墙、PCIe 是否跑在 ×4、驱动与游戏内设置。**把这些排干净，再判断是不是搭配失衡。**

## :material-thermometer: 稳定性与烤机测试

烤机是让硬件短时间高负载，以暴露散热、供电、内存、超频的不稳定。**烤机功耗/温度高于日常，属于「压力测试」而非使用常态，不要 24 小时烤。**

### CPU 稳定性

- **Cinebench（R23 / 2024）**：用渲染测单核、多核分数，跑一圈十几分钟，既能对比性能，也能看温度是否稳定、会不会中途报错，是最温和常用的一关；
- **Prime95（Small FFTs）/ OCCT**：更极端的 CPU 烤机，Small FFT 发热最猛，用来快速验证超频/降压是否稳定，**一般跑 10～30 分钟足够**，温度秒撞墙就说明散热或电压要调整；OCCT 还带电源测试、数据完整性校验。

### 内存稳定性

内存不稳的表现很隐蔽：随机蓝屏、程序闪退、游戏崩溃、文件损坏。

- **TestMem5（TM5）**：常用的内存压力测试，配合 anta777 等严格配置循环跑，**开了 XMP/EXPO 或手动超频后建议跑几轮，0 错误才算稳**；
- **MemTest86**：做成 U 盘启动盘、在进 Windows 之前裸机测内存，最彻底，排查疑难蓝屏时用；
- 测出错误，先回默认频率，再逐步收紧，别一次同时改频率、时序、电压。

### 显卡稳定性

- **FurMark（甜甜圈）**：经典显卡烤机，让 GPU 长时间满载看温度和是否花屏，现代显卡有功耗/温度保护，**跑 10～15 分钟即可，没必要长时间折磨**；
- **3DMark（Time Spy / Steel Nomad 等）**：更接近真实游戏的基准跑分，**循环跑 Stress Test 能得到稳定性百分比**，分数也能和同型号横向对比，判断显卡是否正常发挥。

### 硬盘检测

- **CrystalDiskInfo**：看硬盘健康度、SMART 属性、**通电次数/时间（验二手）**、温度、传输模式；
- **CrystalDiskMark**：测顺序和 4K 随机读写，验证固态是不是跑在应有的通道速度上（若顺序速度异常低，回去查 M.2 通道和 PCIe 链路）。

## :material-microsoft-windows: 蓝屏（BSOD）排查

蓝屏（Blue Screen of Death，蓝屏死机）是 Windows 遇到无法继续运行的内核级错误时的保护停机：系统停止操作、显示**停止代码（Stop Code）**，并把出错现场写入**转储文件（dump）**。蓝屏不代表 Windows "坏了"，而是系统在提示某个内核组件出错；排查的关键是<span class="hl-key">拿到代码、找到转储、按规律定位</span>。

### 第一步：让系统留下转储文件

- 默认设置通常会在 `C:\Windows\Minidump\` 留下小型转储（每次蓝屏一个 `.dmp` 文件），并在 `C:\Windows\MEMORY.DMP` 留下完整转储；
- 确认路径：设置 → 系统 → 关于 → 高级系统设置 →「启动和故障恢复」的设置 → "写入调试信息"选择「小内存转储」或「自动内存转储」；
- 如果蓝屏后**反复自动重启、来不及看代码**，先在同一界面取消勾选"自动重新启动"，代码就会停在屏幕上；也可以不手抄屏幕、直接看转储文件。

### 第二步：用 BlueScreenView 读转储

**BlueScreenView 是 NirSoft 出品的免费小工具（绿色、单文件）**，自动扫描 Minidump 目录，把每次蓝屏的时间、停止代码（Bug Check Code，形如 `0x00000119`）以及**可能导致崩溃的驱动文件名**列出来：

- 上半屏是蓝屏记录列表；下半屏（默认"驱动程序视图"）会高亮可疑模块——如果多次蓝屏都指向同一个 `.sys` 文件（如网卡、显卡、芯片组驱动），排查方向就很明确；
- 双击记录可查看完整参数，菜单可切换显示原始调用堆栈；
- 该工具为免费绿色软件，请从 NirSoft 官网下载；个别杀软可能误报，以官网文件为准。

!!! tip "BlueScreenView 给的是线索，不是判决书"
    高亮的驱动有时只是"事发时在场"，根因可能是内存错误、硬件不稳定或其他驱动。例如内存损坏让显卡驱动执行了错误数据，崩溃模块会显示显卡驱动，但真正该查的是内存。**要结合代码含义、出现频率和最近的改动综合判断。**

### 常见停止代码与排查方向（以微软官方文档为准）

| 停止代码 | 名称 | 通常的排查方向 |
| --- | --- | --- |
| 0x0000000A | IRQL_NOT_LESS_OR_EQUAL | 驱动访问了错误地址：更新 / 回滚驱动，查内存 |
| 0x0000001A | MEMORY_MANAGEMENT | 内存管理错误：内存故障为主，也可能是驱动 |
| 0x0000001E | KMODE_EXCEPTION_NOT_HANDLED | 内核程序异常：驱动、内存、磁盘错误 |
| 0x0000003B | SYSTEM_SERVICE_EXCEPTION | 系统服务异常：常见显卡驱动、内存 |
| 0x00000050 | PAGE_FAULT_IN_NONPAGED_AREA | 访问了无效内存页：内存故障 / 驱动 |
| 0x0000007E | SYSTEM_THREAD_EXCEPTION_NOT_HANDLED | 系统线程异常：驱动兼容性 |
| 0x0000007F | UNEXPECTED_KERNEL_MODE_TRAP | 硬件问题为主：内存、CPU、过热 |
| 0x000000D1 | DRIVER_IRQL_NOT_LESS_OR_EQUAL | 驱动问题（常见网卡 / USB 驱动） |
| 0x00000116 | VIDEO_TDR_FAILURE | 显卡驱动重置超时：显卡驱动、显卡硬件、供电 |
| 0x00000119 | VIDEO_SCHEDULER_INTERNAL_ERROR | 显卡调度错误：驱动 / 显卡 |
| 0x00000124 | WHEA_UNCORRECTABLE_ERROR | 硬件错误：CPU / 内存 / 主板 / 供电，查散热与超频 |
| 0x00000133 | DPC_WATCHDOG_VIOLATION | DPC 超时：驱动（常见存储控制器）、固件 |
| 0xC000021A | STATUS_SYSTEM_PROCESS_TERMINATED | 关键系统进程终止：系统文件、更新失败 |
| 0xC0000225 | STATUS_NOT_FOUND | 启动设备 / 引导文件问题：磁盘连接、引导修复 |
| —（文字代码） | CRITICAL_PROCESS_DIED | 关键进程崩溃：系统文件、磁盘、驱动 |

需要严谨说明：<span class="hl-key">停止代码只指向"错误类别"，不会直接点名某个硬件</span>；同一代码在不同机器上的根因可能不同。代码名称与参数含义以 Microsoft Learn《Bug check code reference》为准：<https://learn.microsoft.com/windows-hardware/drivers/debugger/bug-check-code-reference2>。

### 第三步：怎么搜索代码与定位

- **官方查询**：在 Microsoft Learn 搜索完整代码或名称（如 `VIDEO_TDR_FAILURE`），文档给出每个参数的具体含义；
- **通用搜索**：用"完整代码 + 名称"作关键词（如 `0x00000116 VIDEO_TDR_FAILURE`），优先参考微软官方和硬件厂商支持页，论坛案例只作参考；
- **记录规律**：记下每次蓝屏的时间、代码、可疑驱动、当时在做什么、最近装过什么软件 / 硬件 / 驱动。偶发一次且之后正常，多为瞬时错误；同一代码反复出现，再按对应方向系统排查；
- **排查顺序建议**：①卸载最近安装的驱动 / 软件、回滚驱动；②跑内存测试（TM5 / MemTest86，见前文）；③检查磁盘 SMART 与系统文件（`sfc /scannow`、`chkdsk`）；④检查温度与供电（是否超频 / 降压，先回默认）；⑤仍无法定位时，用完整转储（MEMORY.DMP）到技术社区求助，并附上 BlueScreenView 截图和整机配置。

!!! warning "不要一看到蓝屏就重装系统"
    重装会抹掉排查线索；如果根因是硬件（内存、电源、散热），重装后照样蓝屏。先按上面的步骤拿到代码和转储；只有系统文件大面积损坏、或确认与硬件无关时，重装才是正确选择。

!!! note "DLSS / FSR / 帧生成不是超频"
    它们是**游戏内的超分辨率 / 插帧设置**：用较低分辨率渲染再放大、或在帧之间插帧来换更高帧率，会轻微影响清晰度，帧生成还会增加一点延迟，和「给显卡超频」是两回事。原理与适用场景见《[硬件 · 光追与超分辨率技术](硬件.md#光追与超分辨率技术)》；渲染延迟、输出延迟和显示器刷新率的关系见《[显示器与刷新率](../../外设/显示器与刷新率.md)》。

## :material-tune: 显卡调校：微星小飞机

MSI Afterburner 除了监控，也是显卡微调工具：

- **Core Clock / Memory Clock**：核心、显存频率曲线，小步加，每步用 3DMark 或游戏验证；
- **Power Limit / Temp Limit**：功耗墙、温度墙，适当放开能让高端卡维持更久睿频；
- **Fan Curve 风扇曲线**：自定义「温度—转速」曲线，在噪音和温度间找平衡；
- **降压超频（进阶）**：按 Ctrl+F 打开曲线编辑器，在较低电压点把频率略微上移、再把曲线右侧压平锁定，实现「同性能更低温度功耗 / 同功耗更高频率」；一次约 15MHz 小步试，3DMark 压力测试稳定性 97% 以上、游戏不花屏不掉驱动才算稳，原理见《[硬件 · 显卡超频与调校](硬件.md#显卡超频与调校)》；
- 不稳定的表现是花屏、驱动重置、黑屏，退回默认即可。**不要盲目加电压，刷显卡 BIOS 不建议新手碰**，原理见《[硬件 · 显卡超频与调校](硬件.md#显卡超频与调校)》。

## :material-check-all: 新装机器的一套验证流程

!!! success "建议顺序（一次只加一个负载）"
    1. **识别**：CPU-Z / GPU-Z 核对型号、内存双通道与频率、硬盘容量和通道；
    2. **轻载观察**：HWiNFO 挂着，看待机温度、风扇是否被识别、电压是否正常；
    3. **单烤 CPU**：Cinebench 起步，必要时 OCCT/Prime95 短时验证，盯温度和降频；
    4. **测内存**：开 XMP/EXPO 后用 TM5 跑圈，0 错误；
    5. **单烤显卡**：FurMark / 3DMark 循环，盯核心、热点、显存温度和供电；
    6. **双烤**：CPU + 显卡同时满载，验证电源余量和机箱散热（这步最接近最坏情况）；
    7. **回到真实使用**：微星小飞机 OSD 进常玩的游戏，看帧时间、占用和温度。

!!! warning "几个要记住的边界"
    - 烤机通过 ≠ 永远稳定，但烤机必崩一定有问题；烤机温度高于游戏是正常的；
    - 跑分高低受驱动、室温、分辨率、后台程序影响，**和同型号比区间即可，别纠结一两百分**；
    - 任何超频/降压都以「长期稳定、温度可控」为前提，不稳就回默认，必要时清 CMOS，见《[点亮与故障排查](点亮与故障排查.md)》。
