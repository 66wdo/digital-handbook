# 网速、测速与排障

这一篇解决最实际的问题：**办的宽带到底跑没跑满、怎么测速才不作弊、ping 和丢包怎么看、卡顿时怎么一步步把问题定位到具体某一段**。核心方法和装机排障一样：由近到远、分段测试、一次只改一个变量。

## 网速单位：Mbps 和 MB/s

运营商套餐写的「500M / 1000M」单位是 **Mbps（兆比特每秒）**，而下载软件、文件拷贝显示的是 **MB/s（兆字节每秒）**。换算关系是：

!!! tip "速率换算：兆比特 ÷ 8 = 兆字节"
    **1 字节（Byte）= 8 比特（bit）。** 1000 Mbps 宽带的理论下行峰值 ≈ 1000 ÷ 8 = **125 MB/s**，扣除协议开销和测速折损，有线通常跑到 110 MB/s 上下（约 900 Mbps）就算达标。

几个容易误解的点：

- **带宽是「最高能跑多快」，不是恒定速度**，且家用宽带**下行远大于上行**（如千兆下行可能只有 30～100M 上行）。直播推流、视频会议、往云端传文件、NAS 外网访问看的是<span class="hl-key">上行</span>，很多卡顿其实是上行被占满；
- 「千兆」要整条链路都到千兆：光猫口、路由器 WAN/LAN、网线、网卡、协商速率，<span class="hl-key">任何一环只有百兆，整体就是百兆</span>；
- 带宽大不等于延迟低：千兆光纤如果走了拥塞的出口或拥挤的 Wi-Fi，游戏 ping 一样高。

## 怎么测速才准

「测速」其实要分别回答三个不同问题，混在一起测就会得出错误结论：

1. **宽带本身达不达标** → 用网线把电脑直连路由器（最好直连光猫）、只留这一台设备、关掉代理 / VPN、暂停下载和云盘同步，用 Speedtest 类工具或运营商官方测速，多线程测下行 / 上行；
2. **某个房间 Wi-Fi 好不好** → 人站在那个位置，手机连 **5G / 6G** 测，对比其他位置，这测的是无线覆盖而不是宽带；
3. **内网快不快（电脑 ↔ NAS）** → 用 **iperf3** 测两台设备之间的内网吞吐，或直接看局域网大文件拷贝速度，这与互联网无关。

!!! tip "测速结果怎么看"
    有线直连能跑到签约带宽的 **90% 上下**通常就算达标（运营商的达标承诺一般也按有线测）。无线测速天然要打折：5G 近距离跑到宽带的六七成以上属正常，远了 / 隔墙后下降是物理规律。多换几个测速节点、避开晚高峰，别用单个节点的一次结果下结论。

## 三个核心指标：延迟、丢包、抖动

- **延迟（latency / ping，毫秒 ms）**：一个数据包到对端再回来的时间，由物理距离、经过的路由跳数和设备排队决定。游戏、视频通话、远程桌面对它最敏感；
- **丢包（packet loss，%）**：发出的包有多少没回来。哪怕只有 1%～2% 的丢包，游戏里就可能瞬移、技能延迟，语音会断续；丢包比单纯高延迟更难受；
- **抖动（jitter，ms）**：每次延迟之间的波动。抖动大时平均延迟不高也会一卡一卡，视频会议尤其明显。

## ping：最基础的网络诊断命令

**ping** 向目标发一个探测包（ICMP 回显请求），对方回包，于是你能看到往返时间和有没有丢。

Windows 打开命令提示符（CMD）或 PowerShell：

```text
ping 223.5.5.5            # 测到某个地址，Windows 默认发 4 个包
ping -t 223.5.5.5         # 持续 ping，按 Ctrl+C 停止（观察一段时间的丢包）
ping www.baidu.com        # 直接 ping 域名（同时验证 DNS 解析）
```

返回结果怎么读：

- `时间=xx ms / time=xx ms`：往返延迟，内网通常 `<1ms`，本地到运营商几～十几 ms；
- `时间<1ms`：对方就在你局域网内；
- `请求超时 / Request timed out`：这个包没回来（丢包、对方禁 ping 或不通）；
- `TTL=...`：剩余跳数，可粗略判断系统类型，普通排查不用深究；
- 连续 ping 一段时间，看末尾统计的「丢失 = x (0% 丢失)」，<span class="hl-key">丢包率和延迟波动比单次数值更重要</span>。

| 步骤 | ping 谁 | 通代表什么 | 这一段就丢包 / 高延迟说明 |
| --- | --- | --- | --- |
| ① 本机协议栈 | `ping 127.0.0.1` | 系统网络栈、网卡驱动正常 | 本机网卡驱动 / 系统 / 防火墙问题，与外网无关 |
| ② 内网网关 | `ping 你的网关`（如 192.168.1.1） | 电脑到路由器这一段正常 | **内网问题**：Wi-Fi 干扰 / 距离、网线或协商速率、路由器 LAN、网卡 |
| ③ 运营商出口 | `ping 223.5.5.5`（或 114.114.114.114、8.8.8.8） | 能出到公网 | 网关正常但这一步丢包：**光猫、外线或运营商出口问题** |
| ④ DNS 解析 | `ping www.baidu.com`（域名） | 域名能被解析成 IP | 能 ping 通 IP 却 ping 不通域名：**DNS 问题** |
| ⑤ 目标服务 | `ping 游戏服务器 / 网站` | 到目标正常 | 前面都正常、只有目标异常：**对方服务器或其线路问题** |

!!! success "一张表判断方向"
    - **ping 网关就高延迟 / 丢包** → 问题在家里：无线就查频段、距离、信道、回程；有线就查网线、协商速率、网口；
    - **网关正常、ping 公网 IP 丢包** → 问题在光猫 / 外线 / 运营商，重启光猫路由无效就报修；
    - **能 ping 通 IP、ping 域名失败** → DNS，见下节；
    - **公网都正常、只有某个游戏 / 网站卡** → 对方服务器或跨网线路，不是你家宽带坏了。

### tracert：看数据包经过的每一跳

`tracert -d 目标地址`（Linux / macOS 是 `traceroute`，进阶可用 `mtr`、Windows 的 `pathping`）列出数据包沿途经过的每一个路由器和各跳延迟，用来确认延迟从哪一跳开始陡增：

```text
tracert -d 223.5.5.5
```

`-d` 表示不反查域名、出结果更快。注意：<span class="hl-key">中间某一跳显示超时，只要后面的跳还在正常返回，就不是真断</span>——很多运营商路由器会限制对探测包的回应（ICMP 限速），要看趋势和最终是否到达，而不是看到一个 `*` 就慌。

## DNS：能上 QQ 却打不开网页

**DNS** 负责把 `www.baidu.com` 这种域名翻译成服务器 IP。它出问题的典型症状是：**聊天软件、游戏在线正常（它们可直接连 IP），但浏览器打不开网页、或某些网站特别慢**。

- 验证：`ping 223.5.5.5` 通、`ping www.baidu.com` 报「找不到主机」，基本就是 DNS；
- `nslookup 域名` 可单独测试当前 DNS 能不能解析；
- 处理：在路由器或电脑上把 DNS 换成稳定的公共 DNS（如 `223.5.5.5`、`119.29.29.29`、`114.114.114.114`，海外 `8.8.8.8`、`1.1.1.1`），再用 `ipconfig /flushdns` 清本地 DNS 缓存；
- DNS 只负责「找到地址」，<span class="hl-key">换 DNS 不会提升带宽，也治不好物理丢包</span>，别把它当万能药。

## 常见症状对照

| 症状 | 最可能的方向 |
| --- | --- |
| Wi-Fi 慢，插网线就正常 | 无线：频段（被挤在 2.4G）、距离 / 墙体、信道干扰、Mesh 无线回程 |
| 有线测速也不达标 | 网线 / 网口协商降速、老路由器转发性能、光猫口或宽带本身 |
| 白天正常、晚上高峰卡 | 区域拥塞、共享带宽、2.4G 晚间干扰；跨运营商互访也常见 |
| 下载很快、游戏却高 ping / 丢包 | 延迟问题而非带宽：换 5G/有线、查跨网与出口，升级宽带套餐帮助有限 |
| 视频会议 / 直播卡顿 | 上行带宽被占满、无线丢包抖动；先看上行和 ping 网关 |
| 所有设备一起慢 / 断网 | 路由器 / 光猫 / 外线；看光猫 PON、LOS 灯 |
| 只有某一台设备慢 | 那台设备的网卡、驱动、省电设置、后台占用或信号 |
| 连着 Wi-Fi 但「无 Internet」 | 拨号断了、欠费、外线故障；进路由器看 WAN 状态、看光猫有没有 LOS 红灯 |
| 个别网站 / 游戏连不上，其余正常 | 对方服务器、线路或 DNS，可 tracert + 换 DNS 验证 |
| 能开大部分网页、少数页面 / 图片打不开 | 可能是 MTU 问题（PPPoE 常见 MTU 1492，大包传不过去），路由器里调 MSS / MTU |

补充两个系统侧的高频原因：① Windows 网卡「允许计算机关闭此设备以节约电源」会让网卡空闲降速 / 掉线；② 后台的系统更新、云盘同步、游戏下载、别人在看 4K，会悄悄占满带宽或上行，排查前先确认链路没有被自己人占满。开了代理 / VPN 而节点绕路，也会表现为全局高延迟。

## 什么时候该找运营商

以下情况不是家里设备能解决的，直接报修更高效：光猫 **LOS 红灯**或光功率明显异常、网线直连光猫拨号后测速仍长期不达标、ping 公网 IP 持续丢包且重启光猫无效、某片区域晚高峰规律性拥塞。报修时<span class="hl-key">直接报「有线直连光猫」测得的数据（签约速率、实测、ping 网关与公网的丢包延迟、光信号灯状态）</span>，比一句「网很卡」更能让装维快速定位。
